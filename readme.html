Architectural Design Patterns — Practice Class

  • Question 1 — What a proper architecture gives you?
    • To change one small thing, like the error text, developer must read 600 lines of server, JSON, SharedPreferences and UI code together. One class has many reasons to change. This breaks the Single Responsibility Principle.
    • For example, to just test out only the form validation in login page, developer must launch whole activity on an emulator. Developer cannot change the server for a fake one, because server code is also inside the activity file.
    • If the server changes its JSON format, developer must edit the same file which also holds the UI design, by doing that I can easily break the UI whenever I have to change the server code, for instance.
  • Question 2 — Starting from nothing
    • First of all, developer should understand the app and its requirements. This must be done before choosing any pattern, because pattern depends on the requirements.
    • Developer should learn the pattern before using one. The better developer understands it, the better he can use it.
    • Developer should separate database and server out of Activities into repos.
